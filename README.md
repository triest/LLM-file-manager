# Локальный файловый менеджер

Небольшое Windows-приложение с поиском по содержимому файлов, просмотром извлечённого текста, открытием в установленном офисном приложении и чатом с локальным ИИ. Приложение работает как обычное окно Tkinter, без OpenServer, веб-сервера и облачных API.

## Первый запуск

1. Выполните `CreateShortcut.ps1` (если Windows блокирует сценарий: откройте PowerShell в этой папке и выполните `powershell -ExecutionPolicy Bypass -File .\CreateShortcut.ps1`). Это создаст ярлык `Local File Manager` на рабочем столе.
2. Запустите приложение двойным щелчком по ярлыку.
3. Нажмите **Добавить папку**, укажите нужную папку на N: и нажмите **Сканировать**.

Индекс хранится отдельно в `%APPDATA%\LocalFileManager\files.sqlite3`; сами файлы не загружаются и не копируются. Выбранные папки сохраняются для следующего запуска. Сканер пропускает системные папки и файлы больше 100 МБ.

## Локальные модели на этом компьютере

В локальном хранилище Ollama обнаружены `qwen2.5:3b`, `qwen2.5:7b`, `deepseek-r1:14b`, `qwen2.5vl:7b` и `qwen3-vl:4b`.

- **qwen2.5:7b** — основной выбор из уже установленных для русского чата и правок Word/текста; его короткий ответ проверен с локальной Ollama.
- **qwen2.5:3b** — для более быстрой работы и меньшего потребления памяти.
- **qwen3:14b** — кандидат на более сильную русскоязычную работу с документами, если скачать; размер из каталога Ollama около 9.3 GB. Видеокарта здесь RTX 4060 Ti с 16 GB VRAM, поэтому длину контекста лучше не ставить на максимум.
- **qwen2.5-coder:7b** — рекомендуемая отдельная модель для правок исходного кода, если скачать. В каталоге Ollama указаны 4.7 GB и контекст 32K.
- **deepseek-r1:14b** — уже установлен для сложного анализа и планирования; обычно медленнее в коротком повседневном чате.
- **qwen3-coder:30b** — сильнее для длинных агентных задач с кодом, но занимает около 19 GB и превышает объём VRAM этой видеокарты.
- **deepseek-r1:14b** — более сложные рассуждения, но ответы дольше.
- **qwen2.5vl:7b** и **qwen3-vl:4b** — задачи с изображениями; текущий прототип индексирует текст документов, а не анализирует изображения.

При запуске приложение проверяет Ollama и, если возможно, тихо запускает локальную службу. В настройке Ollama используется найденное хранилище моделей `J:\OllamaModels`. В чате можно подключить Ollama или LM Studio на localhost, обновить список моделей и прикрепить выбранный файл.

ИИ не имеет доступа к файловой системе и не может удалять файлы. Он только предлагает план сортировки. Перемещение и переименование запускаются отдельно пользователем. Правки текста и исходного кода сначала показываются в виде diff. Для Word DOCX модель предлагает правки абзацев, сохраняя остальное содержимое и структуру документа. Можно сохранить изменённую копию или заменить исходник после подтверждения; перед заменой создаётся резервная копия. XLSX/PPTX и OpenDocument доступны для поиска, чтения и открытия в офисном приложении, но их запись пока не поддерживается.

## Форматы

Текстовый поиск и предпросмотр поддерживают DOCX, XLSX, PPTX, ODT/ODS/ODP, TXT, Markdown, CSV, HTML и код. PDF текст извлекается при установленном `pypdf`; установите зависимость один раз командой `python -m pip install -r requirements.txt`. Сканированные PDF без текстового слоя пока индексируются только по имени. Таблицы и презентации индексируются как текст, макет и формулы не анализируются.

Для запуска нужен установленный Python 3.10+ с Tkinter. Остальные функции используют стандартную библиотеку Python. Характеристики моделей сверены с [каталогом Qwen2.5-Coder Ollama](https://ollama.com/library/qwen2.5-coder), [каталогом Qwen3 Ollama](https://ollama.com/library/qwen3) и [каталогом Qwen3-Coder Ollama](https://ollama.com/library/qwen3-coder).
