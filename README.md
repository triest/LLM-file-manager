# Локальный файловый менеджер

Нативное Windows-приложение на Tkinter: локальный поиск, чаты, работа с документами и проектами с полностью локальной языковой моделью. Нет веб-сервера, OpenServer, Ollama, LM Studio или облачных API. Запуск — двойным щелчком по ярлыку.

## Запуск

1. Установите Python 3.10+ с Tkinter и один раз выполните `CreateShortcut.ps1`, чтобы создать ярлык на рабочем столе.
2. Запустите **Local File Manager**.
3. Вкладка **Файлы и поиск**: выберите папки для индексации и папку с моделями либо добавьте несколько отдельных файлов GGUF кнопкой **Добавить GGUF…**.
4. Выберите модель из списка и задайте запрос в чате или вкладке Cursor.

При первом запуске приложение само загружает официальный llama.cpp CUDA runtime и нужные CUDA runtime-библиотеки. Загрузка и распаковка проходят в фоне; окно командной строки и сервер не запускаются. Это однократная загрузка примерно 750 МБ; после неё приложение работает офлайн с выбранными моделями. Журнал установки: `%APPDATA%\LocalFileManager\engine_install.log`. Можно заранее установить CUDA DLL-пакеты командой `python -m pip install -r requirements.txt`.

## Модели

Поддерживаются отдельные GGUF-файлы и каталоги GGUF, а также хранилище с manifest/blob, содержащим GGUF. Можно указать папку с несколькими моделями или выбрать несколько файлов через **Добавить GGUF…**. Выбранные файлы запоминаются в настройке приложения без копирования исходников. Для каждого запроса запускается выбранная модель; после ответа runtime закрывается и освобождает видеопамять. Можно переключаться между моделями из списка в чате и Cursor. Для одной генерации используется одна модель.

В текущем хранилище `J:\OllamaModels` обнаружены пять GGUF-моделей: `qwen2.5:3b`, `qwen2.5:7b`, `deepseek-r1:14b`, `qwen2.5vl:7b`, `qwen3-vl:4b`. Они доступны напрямую из файлов хранилища — запускать Ollama для этого не нужно. Для работы с кодом можно добавить отдельный GGUF, например Qwen Coder, и выбирать его в том же списке. RTX 4060 Ti с 16 GB VRAM подходит большинству моделей до 14B в умеренной квантизации; фактическая скорость и вместимость зависят от формата модели и контекста.

## Вкладки и работа с файлами

- **Файлы и поиск** — локальный индекс выбранных папок, поиск по имени и извлечённому тексту, предпросмотр, ручное переименование/перемещение и предложения сортировки.
- **Чат** — список переписок, выбор модели, рабочая папка, вложения и сохранение ответа в выбранный файл. Доступен обычный чат и режим цели.
- **Cursor** — отдельная вкладка в раскладке «проект слева, редактор по центру, чат справа». Добавляйте в один чат несколько папок проектов — например исходный проект и папку нового проекта; дерево показывает все корни сразу. Открывайте несколько текстовых и кодовых файлов во вкладках, редактируйте их, используйте нумерацию строк, подсветку, поиск и замену в файле, переход к строке, поиск текста по всем корням, навигацию к определениям классов и функций (`Ctrl+клик`/`F12`) и поиск использований функций и переменных (`Shift+F12`). Локальная LLM может предложить фрагмент кода в позицию курсора: сначала он показывается в предпросмотре, после принятия вставляется в буфер; `Ctrl+S` сохраняет его на диск и создаёт резервную копию. Есть базовая поддержка PHP/Laravel: подсветка PHP/Blade, контекст Laravel из `composer.json`, LLM-подстановки и необязательная проверка `php -l` при наличии PHP CLI. PHP CLI, Composer, Ollama и LM Studio приложению не нужны для редактирования. Редактор предупреждает о внешних изменениях и спрашивает перед закрытием несохранённой вкладки. Правки файла по задаче модели по-прежнему показываются отдельным diff и требуют подтверждения.

Интерфейс использует светлую тему в стиле ChatGPT для Windows: мягкий серый фон, белая область беседы, отдельная панель чатов, единые скруглённые кнопки и поле ввода, зелёные акценты.

Модель не получает инструменты файловой системы. Для текстовых, DOCX и Excel правок приложение показывает изменения и ждёт явного подтверждения пользователя. При подтверждённой замене оригинала создаётся резервная копия; можно сохранить отдельную копию. В приложении нет операции удаления. Индекс, конфигурация и история хранятся локально в `%APPDATA%\LocalFileManager`; содержимое не отправляется наружу.

Текстовый поиск поддерживает DOCX, XLS/XLSX/XLSM/XLSB, PPTX, ODT/ODS/ODP, TXT, Markdown, CSV, HTML, PDF* и исходный код. Опциональные парсеры указаны в `requirements.txt`; без них приложение продолжает запускаться, а соответствующий формат пропускается. Изображения и другие бинарные файлы можно прикрепить, но доступность анализа зависит от поддержки формата выбранным runtime/моделью.

## Для разработчиков

Точка входа — `app.py`. Основные правила и проверки описаны в `AGENTS.md` и `SKILLS.md`. Запуск из исходников: `python app.py`. Ядро индексации и запуск Tkinter используют стандартную библиотеку; приложение вызывает свой скрытый `llama-cli` процесс для инференса, без промежуточного сервера.
